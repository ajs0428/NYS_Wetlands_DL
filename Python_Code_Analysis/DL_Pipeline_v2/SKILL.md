# DL Pipeline Code Conventions

Code conventions and patterns for the NYS Wetlands semantic segmentation pipeline (`DL_Pipeline_v2/`).

---

## 1. Module Import Convention

All pipeline files use the `dl_` prefix (e.g., `dl_02_dataset.py`, `dl_losses.py`), making them valid Python identifiers. Cross-module imports use standard Python imports:

```python
from dl_02_dataset import create_dataloaders
from dl_03_unet_model import UNet, get_device
from dl_losses import HybridLoss
from dl_model_utils import load_model
from dl_band_utils import validate_prediction_bands
```

Jupyter notebooks add the script directory to `sys.path` before importing:

```python
import sys
sys.path.insert(0, str(Path("../../Python_Code_Analysis/DL_Pipeline_v2").resolve()))
from dl_02_dataset import create_dataloaders
```

---

## 2. Configuration & Data Flow

**Two-file config system:**

- `dl_band_config.json` — user-editable normalization rules, class names, classification mode
- `normalization_stats.json` — generated by step 01, consumed by all downstream scripts

The stats JSON is the single source of truth for: `in_channels`, `predictor_names`, `band_names`, `label_band`, `class_names`, `ignore_index`, `classification_mode`, `class_weights`, and `normalization` rules.

Scripts read config from stats at runtime — never hardcode band indices, channel counts, or class counts.

---

## 3. Dynamic Band Handling

- Band names are discovered from `rasterio` `.descriptions` at runtime via `discover_bands_from_raster()`
- Predictor bands = all bands minus label band, order preserved
- Prediction rasters can have bands in any order or include extra bands — matching is by name, not position (`validate_prediction_bands()`)
- One-hot expansion (geomorphons) changes channel count dynamically — `compute_in_channels()` accounts for this
- All band handling utilities live in `dl_band_utils.py`

---

## 4. NaN / NoData Handling

- Always use `np.isnan()` — never `val == nan` (IEEE 754: `nan != nan`)
- Two-layer nodata check pattern:

```python
valid_mask = ~np.isnan(band)
if nodata is not None and not np.isnan(nodata):
    valid_mask &= (band != nodata)
```

- NaN label pixels are mapped to `ignore_index=255`, excluded from loss and metrics
- `np.unique()` silently drops NaN — use `np.isnan().sum()` to count nodata separately

---

## 5. ignore_index=255 Convention

- Unlabeled pixels are mapped to 255 everywhere in the pipeline
- `CrossEntropyLoss(ignore_index=255)`, `DiceLoss`, and `FocalLoss` all respect it
- Metrics (accuracy, IoU, confusion matrix) filter `targets != ignore_index` before computation
- Output prediction rasters use 255 as the nodata value for unprocessed pixels

---

## 6. Path Resolution Pattern

All CLI scripts resolve relative paths from the project root:

```python
project_root = Path(__file__).parent.parent.parent  # scripts are 2 levels deep
patches_dir = project_root / args.patches_dir if not args.patches_dir.is_absolute() else args.patches_dir
```

Output directories are created with `mkdir(parents=True, exist_ok=True)` before writing.

---

## 7. Model Architecture Interface

- Any `nn.Module` with signature `(B, C, H, W) -> (B, num_classes, H, W)` is a valid architecture
- `in_channels` has no default — must be provided explicitly from stats
- All architectures implement a `count_parameters()` method
- Architecture is swappable in `dl_04_train_lightning.py` via the `--architecture` arg (`"unet"` or `"resunet34"`)
- Architecture registry lives in `dl_model_utils.py` (`_ARCHITECTURES` dict)

---

## 8. Checkpoint Format & Compatibility

Two checkpoint formats coexist:

| Format | Source | Key | Weight prefix |
|---|---|---|---|
| Legacy | `dl_04_train.py` | `model_state_dict` | none |
| Lightning | `dl_04_train_lightning.py` | `state_dict` | `net.` |

`dl_model_utils.py` auto-detects format and strips the `net.` prefix as needed. Both formats store `in_channels` and `num_classes`.

Checkpoint naming: `best_{mode}_{architecture}-v{N}.ckpt` (Lightning) or `best_model_{mode}.pth` (legacy).

---

## 9. Loss Function Convention

- `HybridLoss` = `FocalLoss` + `DiceLoss` (softmax computed once, shared via `probs` kwarg)
- `FocalLoss` with `gamma=0` reduces to weighted CrossEntropy (legacy compatibility)
- Class weights are computed from inverse frequency, normalized so minimum non-zero weight = 1.0
- Dice averages only over classes present in the batch (avoids score inflation from smoothing on absent classes)
- NaN guard: if focal loss is NaN, falls back to dice-only

---

## 10. Device Handling

- `get_device()` priority: `cuda` > `mps` > `cpu`
- Lightning handles device placement automatically
- Legacy scripts use explicit `.to(device)` calls
- Class weights are registered as Lightning buffers (`register_buffer`) for automatic device movement

---

## 11. Data Augmentation Convention

**Geometric** (applied to both predictors and labels):
- Random horizontal/vertical flips, random 90-degree rotations
- View-based transforms with a single `np.ascontiguousarray()` copy at the end

**Spectral** (applied to predictors only):
- Gaussian noise with sigma in [0.01, 0.03]
- Per-band brightness jitter +/-5%
- All values clipped to [0, 1] after spectral augmentation

Augmentation is enabled only for the training split (`augment=True`).

---

## 12. Normalization Methods

| Method | Formula | Output range | Used for |
|---|---|---|---|
| `min_max` | `(val - min) / (max - min)` | [0, 1] | Most bands (default) |
| `shift_scale` | `(val + shift) / scale` | [0, 1] | Spectral indices (NDVI, MNDWI, NDYI) |
| `one_hot` | Categorical -> N binary channels | {0, 1} | Geomorphons (classes 1-10) |

- Nodata pixels get value 0 in all methods
- `normalize_bands()` is a module-level function in `dl_02_dataset.py`, shared by training and `dl_06_predict.py`
- Normalization rules are defined in `dl_band_config.json`, unlisted bands default to `min_max`

## 13. File Naming Conventions

| Type | Pattern | Example |
|---|---|---|
| Training patches | `{region}_cluster_{N}_huc_{HUCID}_patch_{N}_256m.tif` | `ADK_cluster_11_huc_042900030103_patch_1_256m.tif` |
| Lightning checkpoints | `best_{mode}_{architecture}.ckpt` | `best_multiclass_unet-v2.ckpt` |
| Legacy checkpoints | `best_model_{mode}.pth` | `best_model_multiclass.pth` |
| Training history | `training_history_{mode}_{architecture}.json` | `training_history_multiclass_unet.json` |
| Evaluation metrics | `best_{mode}_{architecture}_evaluation_metrics.json` | `best_multiclass_unet-v2_evaluation_metrics.json` |
| Predictions | `DL_pred_{cluster_info}_{mode}_{architecture}.tif` | `DL_pred_cluster_208_..._multiclass_unetbf64_v2.tif` |
| Probability maps | Same as predictions with `.probs.tif` suffix | `...multiclass_unetbf64_v2.probs.tif` |
| Log directories | `{architecture}_bf{base_filters}_{YYYYMMDD_HHMM}` | `unet_bf64_20260307_2144` |

---

## 14. Docstring & Type Hint Conventions

- All modules have a top-level docstring describing purpose and data flow
- Functions use Google-style docstrings with `Args:` and `Returns:` sections
- Type hints on function signatures using `typing` (`Path`, `Optional`, `List`, `Dict`, `Tuple`)
- Tensor shape conventions documented in comments: `(B, C, H, W)`, `(B, H, W)`, `(num_classes, H, W)`

---

## 15. Rasterio Conventions

- Always use `rasterio.open()` as a context manager
- Band descriptions store band names as metadata
- Output profiles are copied from input with `profile.copy()` and selective `.update()`
- Band indexing is 1-based for `src.read()`

---

## 16. Evaluation & Metrics

- Confusion matrix convention: `cm[true_class, predicted_class]`
- NumPy: computed via `np.add.at(cm, (targets, preds), 1)`
- Lightning: on-device `scatter_add_()` for GPU-native accumulation, reset each epoch with `cm.zero_()`
- Per-class metrics: precision, recall, F1, IoU — all derived from the confusion matrix
- Macro averages over all classes; IoU computed only for classes with `union > 0`
